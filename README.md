# Gather Party：TRPG 團務管理

Gather Party 是部署在 GitHub Pages 的 Firebase 團務管理網站。公開訪客可以查看月曆、瀏覽團務與送出加團申請；GM／管理員登入後可以管理團務與審核申請。另有不需管理員帳號的「快速約團」，讓建立者直接點選候選日期並統計玩家可跑時段。

原本的快速約團版本保留在 `legacy.html`，舊的 `#event=...` 分享資料仍可繼續使用。

## 網站功能

### 公開頁

- 月曆與近期團務列表。
- 顯示日期、時間、主持人、系統、劇本、地點與剩餘名額。
- 玩家填寫名稱、聯絡方式及備註後送出加團申請。
- 已滿員、已過期或由 GM 關閉報名的團務不再接受申請。
- 隱藏團務不會出現在公開頁，也無法透過團務網址直接讀取。
- 月曆日期可直接點選；登入後會開啟已帶入該日期的建團表單。
- 月曆標示台灣國定假日與補假提醒。

### 快速約團

- 建立者／統計者不必是實際 GM，也不需要管理員帳號。
- 直接在月曆點選最多 14 個候選日期，可跨月份選擇。
- 建立者自行定義早上、下午、晚上的實際時間範圍；玩家聯絡方式可選填。
- 玩家每個日期只需選「早上／下午／晚上／X」；同日可複選時段，也可留下備註，儲存後仍能修改。
- 自動整理可成團時段、全員皆可時段與所有玩家的一覽表。

### GM／管理員後台

- Email 與密碼登入。
- 建立、編輯及刪除團務。
- 設定「本團隱藏」與「關閉報名」。
- 將申請設為待處理、核准或婉拒。
- 核准申請會計入已核准人數；取消核准或刪除已核准申請會扣回人數。
- 為日期未定的團務建立可跑團時間調查。
- 可使用日期範圍，或逐行輸入指定日期。
- 每位玩家會取得獨立的 192-bit 隨機私人連結。
- 顯示玩家填寫狀態、全員共同時段及多數可跑時段。
- 清除調查後，所有舊玩家連結會立即失效。

## 第一次啟用

### 1. Firebase Authentication

進入 Firebase Console：

1. 開啟 **Authentication → Sign-in method**。
2. 啟用 **Anonymous／匿名**，讓公開訪客可以送出申請。
3. 啟用 **Email/Password**，讓 GM 與管理員登入。
4. 到 **Authentication → Users** 建立第一個管理員帳號。
5. 複製該帳號的 UID。

### 2. 建立第一位管理員

進入 **Firestore Database**，新增集合與文件：

```text
集合：admins
文件 ID：貼上管理員的 Auth UID
欄位：displayName（string）＝你的管理員名稱
```

新增 GM 時，先在 Authentication 建立帳號，再於 Firestore 新增：

```text
集合：gms
文件 ID：貼上 GM 的 Auth UID
欄位：displayName（string）＝GM 顯示名稱
```

管理員可以管理所有團務；GM 只能管理自己建立的團務。

### 3. 發布 Firestore Rules

到 **Firestore Database → Rules**，以本專案的 `firestore.rules` 完整取代現有規則並發布。

請勿使用測試模式規則。前端的 `firebase-config.js` 是 Firebase Web App 公開設定，不是服務帳戶私鑰；真正的資料權限由 Firestore Rules 控制。

## 日常使用

### 建立團務

1. GM 或管理員按右上角「管理登入」。
2. 登入後按「＋ 開團」。
3. 填寫團名、主持人、系統、劇本、人數、地點、日期、時間、相關連結與說明。
4. 日期尚未決定時，勾選「日期未定」。
5. 視需求開啟「本團隱藏」或「關閉報名」。
6. 儲存後，非隱藏團務會出現在公開月曆與列表。

### 管理加團申請

1. 在管理後台選擇「加團申請」，再選擇團務；也可以從團務列直接按「申請」。
2. 將每筆申請設為待處理、核准或婉拒。
3. 垃圾訊息與測試資料可以直接刪除。

### 建立時間調查

1. 建立一場「日期未定」的團務。
2. 在團務列按「時間調查」，或到後台的「時間調查」頁。
3. 選擇日期範圍或指定日期，並逐行輸入玩家名稱。
4. 建立後，分別複製每位玩家的私人連結。
5. 玩家勾選可跑時段並儲存；同一連結可再次修改。
6. GM 可以查看全員共同時段、多數可跑時段及填寫進度。
7. 確定團期後清除調查，舊連結便會失效。

### 建立快速約團

1. 從上方分頁按「快速約團」。
2. 在月曆點選候選日期，填寫建立者／統計者、實際 GM（可留白）、聯絡方式及成團人數。
3. 依團務需要修改早上、下午、晚上的時間範圍後建立約團表。
4. 把分享連結交給玩家；玩家選時段並填寫備註後，一覽表會即時更新。
5. 左上角的 Gather Party 標誌與「回到團務首頁」都會返回首頁。

## 資料結構

- `managedEvents`：新版正式團務。
- `managedEvents/{eventId}/joinRequests`：加團申請。
- `managedEvents/{eventId}/polls`：時間調查主檔。
- `pollPlayers`：以私人 token 作為文件 ID 的玩家調查資料。
- `quickSchedules`：快速約團主檔。
- `quickSchedules/{scheduleId}/responses`：玩家的快速約團選擇與備註。
- `admins`、`gms`：管理權限名單。
- `events`：舊版快速約團資料，與新版資料分開保存。

## GitHub Pages

在倉庫 **Settings → Pages** 使用 `main` 分支的根目錄發布。合併程式更新後，通常需要等待一至數分鐘才會部署完成。
